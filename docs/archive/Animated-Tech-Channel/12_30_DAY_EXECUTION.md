# 12 — 30-Day Execution Roadmap
*Calendar days are targets, not delivery promises; revise after actual effort and render timing.*

## Week 1 — Discover quality bar and lock concept
- [ ] Day 1: Manually audit 3 reference videos using `templates/reference_audit.md` (opening, first diagram, root-cause reveal and sound).
- [ ] Day 2: Pick channel identity and first episode premise; create private working repo.
- [ ] Days 3–4: Research SQL Server race condition behavior and document sources.
- [ ] Day 5: Polish first draft of `pilot/02_COMPLETE_NARRATION_SCRIPT.md`, read aloud, flag weak sections.
- [ ] Days 6–7: A/B test voice samples, approve commercial license and lock script.
**Exit:** script + selected narrator approved.

## Week 2 — Build animation system and 60s vertical slice
- [ ] Day 8: Set up Node, Codex, Remotion, FFmpeg and Git. Render 5 seconds.
- [ ] Days 9–10: Codex builds visual tokens, request-flow nodes and packet animation.
- [ ] Day 11: Add stock counter, two-customer split-screen and time-lane component.
- [ ] Days 12–13: Sync 45–60 sec to WAV, export proof.
- [ ] Day 14: Review on phone, correct typography, voice pauses and timing.
**Exit:** compelling 60s demo; no extra subscription purchases until this passes.

## Week 3 — Full production
- [ ] Days 15–16: Complete timed scene JSON and storyboards.
- [ ] Days 17–20: Animate remaining scenes chapter by chapter; export low-res reviews first.
- [ ] Day 21: Validate SQL/technical logic in visuals.
**Exit:** full rough-cut MP4 with all necessary events illustrated.

## Week 4 — Edit and launch
- [ ] Days 22–24: Premiere assembly, mix voice/SFX/music, captions.
- [ ] Day 25: Fix continuity, pacing, spelling and sound.
- [ ] Days 26–27: Create 3 original thumbnail variants and description sources.
- [ ] Day 28: Full final QC + upload as unlisted for device checks.
- [ ] Day 29: Publish manually after approval and document baseline metrics.
- [ ] Day 30: Start next episode outline; capture process improvements.
**Exit:** one public, original, high-quality animated technical story.

## Kill/revise criteria
- If 60s demo feels generic: improve motion components and voice before building 8 minutes.
- If 60s render takes excessive manual intervention: simplify character animation and reduce scene variety.
- If costs increase unexpectedly: stop paid calls; preserve source assets and continue with owned voice.
- If technical explanation cannot pass review: rewrite instead of dressing it up with effects.
