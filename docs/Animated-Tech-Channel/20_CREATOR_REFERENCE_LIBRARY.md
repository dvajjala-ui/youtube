## Which three references to use for one episode?
- **Story:** Pouria's *incident-first* chapter progression; do not match any episode's actual words, timing or exact scenes.
- **System diagram:** ByteByteGo for readable infrastructure and service relationships.
- **Technical correctness:** Reducible / Core Dumped for animate-the-state approach.
- **Optional cinematic tension:** fern, but only if the story genuinely warrants it.

## Production-stack truth table
- **Known, creator-disclosed:** ByteByteGo uses Illustrator/After Effects for the referenced video; Reducible has released Manim-based code; Branch Education describes research, storyboard, Blender, voice-led timing, accuracy review and sound design.
- **Unverified:** What AI (if any) Pouria uses, how Pouria creates character motion, and which TTS/narration provider produces that channel's voice.
- **Do not mistake:** A channel's polished animation for proof of AI one-click production. Most techniques still require art direction, animatics and scene-specific motion.

## Watch-study protocol
For each example, record five timestamped segments: hook, first explanation, complication, reveal, resolution. Watch at normal speed with headphones, then mute and watch the same section. Fill `templates/reference_scene_audit.csv`. Report only what you directly observe. If you haven't watched or listened to it, mark **NOT OBSERVED**.

## Important creator-market lesson
There is plenty of overlapping technical subject matter (e.g. databases, servers, load balancers). Our differentiator is *the specific incident, demonstration, original script and visual system*. Topic overlap alone is normal; copied expression is not.
