# 06. 30-Day Execution Plan

Assumption: about 10 to 12 hours per week. If you have less time, stretch each week to two weeks. Do not skip steps.

---

## 1. Plan at a glance

| Days | Focus | Output |
|---|---|---|
| 1 to 3 | Setup | Tools installed, repo ready, test render done |
| 4 to 7 | Study the reference | Filled teardown worksheet (3 videos) |
| 8 to 12 | Component library | 9 components working in Remotion |
| 13 to 17 | Script and voice (video 1) | Locked script, clean voice WAV |
| 18 to 23 | Animate and edit (video 1) | Rendered and edited video |
| 24 to 26 | Publish video 1 | Live video, thumbnail, description |
| 27 to 30 | Review and start video 2 | Metrics notes, video 2 script draft |

---

## 2. Day-by-day

### Days 1 to 3: Setup
- [ ] Follow the setup checklist in file 02
- [ ] Create the channel (own name, simple banner, About text in your own words)
- [ ] Add AGENTS.md from file 04
- [ ] Render one test video with a single Node component

### Days 4 to 7: Study the reference
- [ ] Watch 3 of his videos with the worksheet from file 01
- [ ] Copy the transcripts, send them to me for analysis
- [ ] Write your own style sheet: palette, fonts, shapes, pace

### Days 8 to 12: Component library
- [ ] Theme file
- [ ] Node, Link, Packet
- [ ] Queue, Cluster, Timeline
- [ ] Caption, Highlight, CodeBlock
- [ ] One demo composition that uses all of them

### Days 13 to 17: Script and voice
- [ ] Pick topic (see section 3)
- [ ] Research and outline
- [ ] Write script, read aloud, lock it
- [ ] Record voice, clean it in Premiere
- [ ] Make cues.json

### Days 18 to 23: Animate and edit
- [ ] Storyboard
- [ ] Build scenes with Codex, section by section
- [ ] Render
- [ ] Edit in Premiere, captions, export

### Days 24 to 26: Publish
- [ ] Title, thumbnail, description with sources and repo link
- [ ] Private upload, watch fully on phone
- [ ] Publish

### Days 27 to 30: Review
- [ ] Note CTR and average view duration in YouTube Studio
- [ ] Find the point where most viewers leave
- [ ] Write 5 lessons in a "mistakes" file
- [ ] Draft script for video 2

## 3. Topic shortlist (from your own stack, not from his videos)

| # | Topic | Why it works |
|---|---|---|
| 1 | How SQL Server locks rows and why deadlocks happen | You have seen this in production. Easy to visualize |
| 2 | Why retries can make an outage worse (backoff and idempotency) | Universal, strong hook |
| 3 | How a message queue promises delivery (at-least-once vs exactly-once) | Fits Azure Service Bus style systems |
| 4 | How a database index finds your row (B-tree) | Classic, visual, evergreen |
| 5 | What really happens inside the ASP.NET Core request pipeline | Fits your stack, less crowded |

Pick criteria: (a) you have real experience, (b) you can explain it in one sentence, (c) it can be shown with boxes and arrows.

Recommended first video: #2 (simple visuals, strong hook, small scene count).

---

## 4. Success checks after 30 days

| Check | Target |
|---|---|
| Videos published | 1 (2 is a bonus) |
| Component library reusable | Yes |
| Script to publish time for video 2 | Lower than video 1 |
| Average percentage viewed (Studio) | Note it, improve it on video 2 |
| CTR (Studio) | Note it, test a new thumbnail on video 2 |

Do not judge the channel by views in the first 30 days. Judge it by process speed and quality.

---

## 5. If you fall behind

- Cut scope: fewer scenes, shorter video (6 to 8 min first)
- Never cut: script read-aloud, voice cleanup, QA
